## 1. The native transfer fast path — the only planned-and-unwritten thing

**Planned in** [`2026-08-12_12h49.phase-5-native-fast-path.session.md`](./2026-08-12_12h49.phase-5-native-fast-path.session.md),
displaced by the draft-and-apply arc and never picked back up.

Two folders **inside one backend** — two `ScopedAdapter`s over one Drive, a server reconciling two
roots on one filesystem — currently move every byte out of the backend, through the process, and back
in. The planning session found the plan named one site and there are two: the cross-node transfer in
`fetchContent()`, and `copy()`, which stages a conflict copy inside a single folder and is
intra-adapter already.

**Why it is still open**: invisible to a consumer, blocks nothing, and correctness never depended on
it. **Why it is the natural next session**: it is the only work already thought through, and the
thinking is on disk.

## 2. `location` is never asked

The same file renamed differently on each side. One path wins deterministically, no content is at
risk, and it stays out of `pending` — `needsDeciding` excludes it explicitly
([sync.ts:463](../src/sync.ts#L463)).

It is in the catalogue anyway, marked `asked: never by default`, for two reasons: a consumer may want
to opt into being asked, and leaving it undocumented invites the same question every time somebody
reads the merge.

**Why it is still open**: nobody has asked for the opt-in. Adding an option for a hypothetical
consumer is the speculative work this project keeps refusing. **What it would cost**: an option
naming the reasons a caller wants raised, and one predicate change. Small, and worth nothing until
somebody wants it.

## 3. `eol` and `size` have no durable value

The most defensible of the remaining gaps, and the one to reach for if a consumer complains.

`textReason` (`block | eol | size | no-base | unreadable`) lives for one pass. `CopyReason`
(`binary | block | delete-edit | kind`) lives on the parked copy in `vfs.json` and is read back by
`node.conflicts()` months later. As of `2844684` they overlap in `block`, which the text merge now
stamps onto the copy.

`eol` is the interesting omission: **it is a standing condition of the folder, not an accident of one
pass.** One peer writes CRLF and the other LF, and every text conflict between them will decline for
the same reason until somebody normalises the terminators. A resolver reading the copy later is told
`binary`, which is true enough — it could not be merged — but useless: it hides a fix that would
settle this file and every other one.

**Why it is still open**: giving it a durable value widens a type that travels to every peer's
`vfs.json`, and nobody has asked. **What to check first**: `reason` is not in `DIGEST_FIELDS`
([vfs-file.ts:31](../src/vfs-file.ts#L31)), so adding values cannot break convergence — a peer that
does not know a value still agrees on `state`.

## 4. The explorer has three tests and the library has 537

The three cover the wiring nothing else covers: a stopped pass reaches a person, their answer reaches
`sync()`, and the auto-sync tick opens nothing. Everything else in a 2,287-line model — the tree, the
browser, the caches, Drive, the details pane — is uncovered.

**Why it is still open**: the last session claimed a suite was a session of its own, and was wrong
about it (§88). The model boots under Node with no DOM, and a subscriber standing in for a user is
exactly what the components are, so the cost of each new test is now a fixture, not infrastructure.

**Where to start if this is picked up**: `openVfsTab` + `syncAll` against MemFS covers most of the
model in one fixture; Drive and FSA need adapter fakes and are a different problem.

## 5. Given up on purpose, listed so nobody rediscovers them as bugs

- **Historical content.** There is no object store, so a previous version cannot be recovered. That
  is the trade that buys a folder you can open in Finder and a state readable in one request.
- **Deduplication** between identical files, given up with the same store.
- **Resumable uploads to Drive** — uploads buffer whole. Streaming bounds memory, not bytes moved.
- **Delta transfer** — a changed file travels in full.

All four are in the README's [Todos](../README.md#todos) with the same framing.

## 6. What the last session would tell the next one

Written down because it cost four defects to learn, and it is not in any doc:

**Every defect in that session was found by writing the thing that *uses* the feature, not by reading
the code that implements it.** Three throwaway probes, a retry loop copied from a consumer's sketch,
and a fifty-line headless user each cost minutes, and each found something that careful design
review had missed — including two cases of silent data loss and one that left two folders in
different states after a pass that reported success.

The corollary, also earned: **a test can hold a bug in place.** `CopyReason 'block'` was declared in
the type, documented with a UI recommendation and named in the contract, and never written — because
one test asserted the wrong label, and the code listens to the test rather than to the three
documents.
