## 3. The correction: the fake that was blocking cluster A already exists

Three capitulations in a row have deferred the pickers with the same sentence — *"they need a
stand-in for the File System Access picker and one for Google Identity Services, and nobody has
written either"*. I went to write them. **Half of it has been in the repo the whole time, and is
already being used:**

| What was said to be missing | What is actually there |
| --- | --- |
| a File System Access picker stand-in | [`browser-adapters.test.ts:91-117`](../test/browser-adapters.test.ts#L91-L117) drives `FSAAdapter.pick()` through `stub('window', { showDirectoryPicker })` over a `FakeDirectoryHandle`, and asserts the options it was called with |
| a `FileSystemDirectoryHandle` fake | [`test/fake-handle.ts`](../test/fake-handle.ts), used by every FSA and OPFS test |
| a Google Drive stand-in | [`test/fake-drive.ts`](../test/fake-drive.ts) — an in-memory Drive REST API, already running the whole adapter contract |

So `pickFsaSource` and `pickFsaVfs` need **no new fake at all**: the `stub`/`unstub` helper moves out
of `browser-adapters.test.ts` the way `browsing()` moved out of the cache suite, and the picker
returns a `FakeDirectoryHandle`.

What is genuinely absent is smaller than the sentence implied: **a Google Identity Services stub**
— `window.google.accounts.oauth2.initTokenClient` returning an object with a `callback` field and a
`requestAccessToken()` that calls it — and a **`localStorage` stand-in**, which is a Map behind four
methods. Together they are perhaps thirty lines, and `gis.ts`'s own `loadGis` is skipped entirely
when `window.google` is already there.

**The rule this buys, and it is the sibling of the last one**: *a reason for not doing something ages
as badly as a measurement.* "It needs a fake nobody has written" was true when it was first written
and was copied forward three times without anyone opening the test folder. The check cost one grep.

## 8. Rules this project paid for, carried forward

- **Defects are found by writing the thing that *uses* the feature**, not by reading the code that
  implements it.
- **A test can hold a bug in place** — by asserting a wrong label, *and* by depending on one being
  written. Both have now happened.
- **Write the detector before the fix, and expect it red.** Two of this round's thirteen tests were
  written as detectors and failed on exactly the two defects and nothing else.
- **A green test proves nothing until the fix is mutated out from under it**, and the count of tests
  each mutant kills is the evidence that a test is specific.
- **A mutant list written from the code is not a cover.** Write it, then map it back onto the tests.
- **What is left has to be measured with the same instrument each time.**
- **New — a reason for not doing something ages as badly as a measurement.** §3. Re-check the
  blocker, not just the item.
