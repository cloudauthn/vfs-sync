## 3. The fixture: three refusals, no fakes

All three are reachable through the model with a `MemoryAdapter`, because the model's own wiring
allows it — both facts verified in the source rather than assumed:

- **Edges are a chain of consecutive peers** ([model.ts:639-643](../explorer/src/model.ts#L639-L643)),
  so **two tabs are exactly one edge**, and one `syncAll()` is one pairing question.
- **A peer's id is its folder's basename** ([model.ts:623](../explorer/src/model.ts#L623) with
  [1284](../explorer/src/model.ts#L1284)), so two folders named `twin` under different parents open as
  two peers that both claim `twin`.

| Refusal | Setup |
| --- | --- |
| `foreign-mesh` | four roots on one `MemoryAdapter`; `a⇄b` and `c⇄d` synced **through the engine**, then `b` and `c` opened as tabs — the model's version of [pairing.test.ts:163](../test/pairing.test.ts#L163) |
| `peer-collision` | two roots whose basenames match (`one/twin`, `two/twin`), both opened as tabs |
| `version-unreconcilable` | a root whose `.vfs/vfs.json` carries `version: CURRENT_VERSION + 1`, as [pairing.test.ts:690](../test/pairing.test.ts#L690) writes it |

The groups are established **outside** the model on purpose: syncing them inside it would need the
edge chain to cooperate, and the fixture would end up testing `syncAll`'s ordering instead of the
dialog. `browsing()` already lays roots down this way.

New file: `test/explorer-decide.test.ts`. The sync suite asks whether a pass settles; this one asks

## 4. What has to hold

Twelve properties, one test each unless noted.

**A pairing row is about two folders, not a file**

1. `path` is absent, and the two sides read as folder summaries — item count, and `has never synced`
   / `has synced before` on the right side of each.
2. A side whose format cannot be read carries `· unreadable format`; one that can, does not.

**The `foreign-mesh` question**

3. The note names the consequence in both directions: every file stays, **deletions may come back**.
   Asserted on the sentence, since it is the whole of what a person is told.
4. The two `adopt` choices name both groups and both directions, and **neither says "merge"** —
   asserted as an absence, because that is the regression the label exists to prevent.
5. Answering `adopt` from the dialog settles the edge end to end: the second pass writes, the loser's
   files are all present afterwards, and the winner's `syncId` is the one that was named. This is the
   only property here that reaches through to the folders — without it, the labels could be right and
   the wiring wrong.
6. Refusing the dialog ("Not now") writes nothing and leaves both folders exactly as they were, and
   the log says so.

**The `peer-collision` question**

7. The note says one folder is a copy of the other, and the choices offered are `reidentify` — one
   per side, each naming which one keeps its identity.
8. Answering it settles: the pass applies, and the side that did not keep the identity has a new one.

**The contract, asserted through the dialog**

9. For every conflict the dialog shows, its `choices` are exactly `legalAnswers(reason)` plus
   `abort`, in the catalogue's order. One test over the three pairing reasons — this is the property
   that keeps the dialog from drifting from [`docs/conflicts.yaml`](../docs/conflicts.yaml), and it is
   asserted against `legalAnswers` rather than a hand-written list, which would be a second catalogue.
10. `version-unreconcilable` offers **only** "Leave it for now": `legalAnswers` admits `abort` alone,
    and the note names the format version this build writes.

**The two entry-level notes that never ran**

11. `kind`: a file and a folder on one path, where the folder's subtree is counted — *"takes N
    item(s) with it"* — and the count is dropped when there is nothing under it. Two assertions, one
    test.
12. `delete-edit`: one side deleted it, the other changed it.

**Reachability caveat, stated in advance.** §10 assumes `VFSNode.open` accepts a store one version
ahead and that the refusal comes from the *sync*, which is how `pairing.test.ts` reaches it. If
`openVfsTab` cannot open that tab at all, the note stays uncovered, and the walkthrough says so
rather than reaching for a seam that exists only for the test. The other eleven are reachable with no
such assumption.

## 9. The two defects

### 9.1 A copied folder was offered two buttons that read the same

`peer-collision` is two folders claiming one `peerId`. `folderSide` labels each side with that id, so
the dialog offered:

```
twin keeps its identity      ← reidentify, side a
twin keeps its identity      ← reidentify, side b
Leave it for now
```

Two identical sentences, doing different things: one folder keeps the name it has, the other is
issued a new one. The `<dt>` list above them read `twin` / `twin` as well, so nothing on the screen
told them apart — and `Modal.tsx` keys both the sides and the buttons by their label, so the two
collided as Preact keys too.

Fixed by `distinguish` ([model.ts:432](../explorer/src/model.ts#L432)): where the two labels are
equal, they are told apart by their position in the row — `twin (first)` / `twin (second)` — which is
the order the sides are already listed in, with each one's detail beside it. Position rather than a
fact from the payload because **two copies of one folder can agree on every field it carries**: item
count, `everSynced`, format. There is no fact guaranteed to differ, so a rule built on one would work
until the day it mattered.

### 9.2 A pass that was refused reported that every root was in sync

`syncAll` ended with `if (changed.length === 0) this.log('every root already in sync')` regardless of
why nothing changed. Both ways of declining a pairing question therefore ended with that line — and
`lastMessage` is what [`Footer.tsx:20`](../explorer/src/components/Footer.tsx#L20) shows:

| What the person did | Last line they were shown |
| --- | --- |
| closed the dialog ("Not now") | *every root already in sync* — under `left for later, nothing written` |
| answered every row `abort` | *every root already in sync* — **the only line written at all** |

Two folders that the engine refuses to merge are not in sync, and the second case said nothing else.
Fixed at [model.ts:2092](../explorer/src/model.ts#L2092): an edge that stopped writes no summary at
all, so the specific line above it stands; a pass where every edge came back `applied: false` says
`nothing written`, which is the vocabulary the single-edge path
([`syncTargetCommon`](../explorer/src/model.ts#L1885)) already used. That asymmetry is the reason the
defect existed on one path and not the other.

## 10. One existing test had to change, and why that is the finding

`explorer-sync.test.ts`'s *"reports what stopped it once, and again only when the dispute changes"*
counted passes of the auto-sync timer by grepping the log for `in sync` or `converged` — **the line
§9.2 removed**. The property it asserts is unaffected; its heartbeat was the sentence that was
lying.

It now counts passes off `model.syncing`, which every pass raises whatever it ends up logging. That
is this repo's *"a test can hold a bug in place"*, arriving a second time and from a new direction:
the first one asserted a wrong label, this one **depended on a wrong label being written**. A test
that reads the log to know that something happened is coupled to the wording of the log, and the
wording is the thing most likely to be wrong.

## 12. What the plan got wrong

**§4.11's second half is unreachable and was dropped.** The plan asked for the `kind` note with no
subtree count — *"A file and a folder want this name."* — and there is no way to produce it: a
directory is in the store only while it holds something, so deleting its last child drops the
directory entry along with it, and `subtree` is never 0 on the side that is a folder. Verified by
building exactly that folder and watching both entries leave `live()`. The test says so where the
assertion would have been, and mutant 11 was rewritten to something the reachable half notices.

That statement and one other — `decisionNote`'s `default`, which only `location` reaches, and
`location` is never asked — are the **two statements of the 41 that this session did not close**.
Cluster B goes 41 → 2, and both survivors are unreachable for reasons written down rather than
unexplained.
