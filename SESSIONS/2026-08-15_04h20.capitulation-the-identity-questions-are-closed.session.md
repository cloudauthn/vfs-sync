## 1. What closed since the last capitulation

The item that backlog's extension put at the top — *a question nobody can answer* — is closed. It
took **two sessions rather than one**, and the split is the interesting part.

### 1.1 `7110772` — one name is not one file

[session](./2026-08-14_19h12.identity-adoption.session.md). Three peers each creating `notes.txt` on
their own could end up asking a person which of two **byte-identical** files keeps the name, with the
outcome depending on the order their uuids happened to sort in.

What landed is smaller than either draft: no format change, no alias, no wipe.

> A uuid inside a mesh is minted once and never rewritten. Matching by path may only make two entries
> one file where the answer cannot be wrong: a folder that has never synced, two directories, or two
> files with the same hash.

Twenty-two lines in `merge.ts` and a `joining` flag per side in `sync.ts`.

**The number worth keeping**: the detector went in first — `settle()` refuses a conflict whose two
sides carry the same hash — and with it in place and no fix, `convergence.test.ts` failed **1–3 of
its 16 seeds on every run**, differently each time. That property test had been driving this defect
over a hundred random histories without noticing, because `stabilise()`'s automatic `keep-both` was
converting every occurrence into a silent duplicate file.

### 1.2 `71c7803` — the answer names a winner

[session](./2026-08-15_03h17.mesh-adoption-names-a-winner.session.md). Step 4 of the previous plan,
carried since as the README's first todo: answering `foreign-mesh` stops meaning *authorise* and
starts meaning *choose*. The named group survives; the other folder discards its `.vfs` and rejoins
as a folder that has never synced, with every byte of content untouched. The decision travels in a
new header field, `absorbed`, which converges by union like `text`, so a straggler of the losing
group that was offline throughout rejoins **without being asked again**.

`merge.ts` was not touched — a discarded folder has `syncId === null`, which §1.1's rule already
treats as the one side that may take the mesh's identities. The entry-level half of that work was a
consequence rather than a change.

**Eight mutants, eight killed**, and four of them killed by exactly one test each — which is what
makes those tests specific rather than merely present.

### 1.3 The correction this round produced, twice

Both sessions found a green test that could not fail for the reason it claimed:

- §1.1 deleted an end-to-end test that passed **twelve times out of twelve** with the fix mutated out.
- §1.2 rewrote an invariant test whose two meshes held the same path with *identical bytes* — which
  pair by hash under a rule that has nothing to do with what was under test.

Neither was found by reading. Both were found by mutating the code and watching the suite stay green.

## 2. What is left

### 2.1 The explorer's browse lifecycle — the only item with work in it

Ten methods of `explorer/src/model.ts` that **no test calls at all** (established by grep over
`test/`, not inferred from a coverage percentage):

`newBrowseFolder`, `deleteBrowseEntry`, `removeSource`, `regrantSource`, `selectSource`, `closePeer`,
`toggleDir`, `selectRoot`, `toggleLog`, `clearLog`

Two of them are destructive — [`deleteBrowseEntry`](../explorer/src/model.ts#L1194) removes a folder
and everything inside it after closing the tabs that hang off it, and
[`removeSource`](../explorer/src/model.ts#L1227) closes every tab of a source and drops the Drive
token. The reading found nothing wrong with them: the sibling-prefix hazard a reviewer reaches for
first is already guarded with a trailing slash, in
[`deleteBrowseEntry`](../explorer/src/model.ts#L1206) and in
[`forgetSubtree`](../explorer/src/model.ts#L991), the latter with the comment *"`one` must not take
`one-b`"*. So this is a regression lock and a coverage gap, **not a defect hunt** — which is a
different and weaker justification, and worth saying plainly rather than dressing up.

**Why it is cheap**: the fixture exists twice over. `browsing()` in
[`explorer-cache.test.ts`](../test/explorer-cache.test.ts#L17) boots the model under Node with a
counted `MemoryAdapter` and two vFS roots, and `prompting()` in
[`explorer-model.ts`](../test/explorer-model.ts#L169) is already the stand-in for a person at a
confirm or prompt dialog — which is exactly what the two destructive methods wait on.

**Why it stays out of the README**: it is a gap in this repo's tests, not in what the package does.
The explorer is not in the package's `files`.

### 2.2 The browser pickers — still behind fakes that do not exist

`pickFsaSource`, `pickFsaVfs`, `connectGDrive`, `addGDriveSource`, and `gis.ts` at 6.97 %. They need
a stand-in for Google Identity Services and for the File System Access picker, which is a different

### 2.3 `eol` and `size` have no durable value

Unchanged from §3 of the previous capitulation. A text merge that declines because the two sides
disagree on line terminators parks the copy as `binary` — true, but it hides a fix that would settle
every file in the folder. Safe to widen whenever somebody asks: `reason` is not in `DIGEST_FIELDS`,
so a peer that has never heard of a new value still agrees on `state`.

### 2.4 `location` is never asked

Unchanged from §4 of the previous capitulation. Deterministic, nothing at risk, in the catalogue
marked `asked: never by default`. It would cost an option naming the reasons a caller wants raised,
plus one predicate change. Not before somebody wants it.

### 2.5 New, and permanent: what the mesh work costs for ever

Both were accepted in `71c7803` with the reasoning written down, and both are now in the README so
they are not rediscovered as bugs:

- **`absorbed` is never pruned.** One `syncId` per group ever absorbed. *"Every straggler has
  arrived"* is not a question a mesh can answer, so there is no moment at which dropping one is safe.
- **The winner keeps a peer mark for the identity the loser gave up.** A few dozen bytes, never read;
  pruning it needs the same unanswerable question.

## 6. Rules this project paid for, carried forward

The two from the previous capitulation, plus what this round added. None of them are in any doc, and
each cost defects to learn.

- **Defects are found by writing the thing that *uses* the feature**, not by reading the code that
  implements it.
- **A test can hold a bug in place.** `CopyReason 'block'` was declared, documented and named in the
  contract, and never written, because one test asserted the wrong label and the code listened to the
  test rather than to the three documents.
- **New — write the detector before the fix, and expect it red.** §1.1's two-line assertion in a
  shared helper turned a property test that had been silently absorbing the defect for a hundred
  histories into one that failed 1–3 seeds a run. A defect that a suite converts into a plausible
  result is invisible until something refuses to accept the result.
- **New — a green test proves nothing until the fix is mutated out from under it.** Both sessions
  this round produced one that passed for a mechanism other than the one under test. Mutation is now
  the standard for anything claiming an invariant, and the count of tests each mutant kills is the
  evidence that a test is specific.
