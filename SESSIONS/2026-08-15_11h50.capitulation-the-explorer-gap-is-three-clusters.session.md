## 2. The correction this round produces: three clusters, not one

§18 of that walkthrough said the residual gap was *"exactly the pickers"* — one cluster with one
reason. **Measured today, that is false.** `model.ts` has **1 547 statements, 298 of them never
executed**, and they fall into three groups:

| | Cluster | Uncovered statements | What it needs |
| --- | --- | --- | --- |
| **A** | the pickers and Google Identity Services | **88** in `model.ts`, plus **80 of 86** in `gis.ts` | two fakes that do not exist |
| **B** | the decide dialog's **pairing** half | **41** | nothing — it is reachable from a plain sync |
| **C** | failure branches inside methods that are otherwise covered | **169** | nothing, and no session |

Cluster A is `pickFsaSource` (25), `pickFsaVfs` (25), `connectGDrive` (19), `addGDriveSource` (13),
`restoreGDrive` (2) and the two Drive getters (4).

Cluster B is `decidable`'s pairing branch (19), `decisionNote` (13) and `folderSide` (9) — §3.1.

Cluster C is a scatter across some thirty methods, largest first: `loadDetails` (25),
`syncTargetCommon` (13), `openVfsTab` (11), `deleteFile` (11), `renameFile` (10), `boot` (10),
`snapshotOf` (9), `buildNewTab` (8), `compare` (8), `withTimeout` (14), and a long tail of one- and
two-statement `catch` blocks.

**Why the claim was made in good faith, and what to do about it.** The walkthrough counted *methods
that no test names*, by grep over `test/`. By that instrument the answer really was "the pickers":
every other method is called by something. The statement counter asks a different question — *which
lines never run* — and a method whose happy path is driven and whose `catch` never fires passes the
first test and fails the second. Both readings are true; only the second is what a person means by
"what is left untested".

**The rule this buys**, and it is new: **what is left has to be measured with the same instrument
each time.** A ledger that switches between "no test names this" and "these lines never ran" reports
progress it did not make.

The engine's identity work landed this round and the one before it (`7110772`, `71c7803`) and is
tested at the engine level in [`test/pairing.test.ts`](../test/pairing.test.ts). **The words a person

- `decidable`'s `adopt` and `reidentify` choice blocks
  ([model.ts:2242-2260](../explorer/src/model.ts#L2242-L2260)) — including the label

Grep confirms it: no test under `test/explorer-*` contains `foreign`, `collision`, `adopt` or

It needs no fakes. `syncAnswering` → `askDecision` → `decidable` is the path any explorer sync takes,
and `test/pairing.test.ts` already shows how to construct all three pairing refusals.

## 7. Rules this project paid for, carried forward

The four from before, plus this round's two. None are in any doc, and each cost a defect to learn.

- **Defects are found by writing the thing that *uses* the feature**, not by reading the code that
  implements it.
- **A test can hold a bug in place.** `CopyReason 'block'` was declared, documented and named in the
  contract, and never written, because one test asserted the wrong label and the code listened to the
  test rather than to the three documents.
- **Write the detector before the fix, and expect it red.**
- **A green test proves nothing until the fix is mutated out from under it**, and the count of tests
  each mutant kills is the evidence that a test is specific.
- **New — a mutant list written from the code is not a cover.** Write it, then map it back onto the
  tests; the holes are where the decoration is.
- **New — what is left has to be measured with the same instrument each time.** §2.
