`explorer/src/model.ts` (2,287 lines) stands at **59.37% of statements and 64.42% of functions — 37

- **The sync surface a person actually clicks**: `syncTarget`, `syncTargetWithConfirm`,

**Why it is still open**: it is internal. The explorer is not in the package's `files`, so nothing
here reaches a consumer, and every guarantee the README makes is held by the library's own suite.

no DOM, its `sources` are plain data, and a subscriber standing in for a person is exactly what a
component is. The cost of the next test is a fixture, not a harness.

**Where to start**: `resolveConflict` and the `syncTarget*` family, on the fixture
`explorer.test.ts` already uses. They are the paths a person drives by hand, they are where the
library's stop-and-ask contract meets a UI, and they are the last places in this repo where a wrong
answer could reach `sync()` unobserved.

## 3. `eol` and `size` have no durable value

The most defensible of the remaining gaps, and the one to reach for if a consumer complains.

Two vocabularies, one of which survives the pass:

| Type | Values | Lifetime |
| --- | --- | --- |
| `TextMergeReason` ([diff3.ts:23](../src/diff3.ts#L23), [merge.ts:64](../src/merge.ts#L64)) | `block`, `size`, `eol`, `no-base`, `unreadable` | one pass |
| `CopyReason` ([types.ts:186](../src/types.ts#L186)) | `binary`, `block`, `delete-edit`, `kind` | parked on the copy in `vfs.json`, read back by `node.conflicts()` months later |

They overlap in `block` since `2844684`. `eol` is the interesting omission, because **it is a
standing condition of the folder, not an accident of one pass**: one peer writes CRLF and the other
LF, and every text conflict between them declines for the same reason until somebody normalises the
terminators. The resolver reading that copy later is told `binary` — true enough, it could not be
merged — which hides a fix that would settle this file and every other one.

**Why it is still open**: it widens a type that travels to every peer's `vfs.json`, and nobody has
asked. **What makes it safe when somebody does**: `reason` is not in `DIGEST_FIELDS`
([vfs-file.ts:31](../src/vfs-file.ts#L31)), so a peer that has never heard of a new value still
agrees on `state`. Convergence cannot break on this.

## 4. `location` is never asked

The same file renamed differently on each side. One path wins deterministically, no content is at
risk, and it is excluded from `pending` by name — [sync.ts:463](../src/sync.ts#L463).

It is in [`docs/conflicts.yaml`](../docs/conflicts.yaml) anyway, marked `asked: never by default`, so
that reading the merge does not raise the same question every time. The catalogue has no `known_gap`
entries left, and `legalAnswers(reason)` is that catalogue in code, so this cannot drift quietly.

**Why it is still open**: nobody has asked for the opt-in, and building it for a hypothetical
consumer is the speculative work this project keeps refusing. **What it would cost**: an option
naming the reasons a caller wants raised, plus one predicate change.

## 5. Given up on purpose, listed so nobody rediscovers them as bugs

- **Historical content** — no object store, so a previous version cannot be recovered. The trade that
  buys a folder you can open in Finder and a state readable in one request.
- **Deduplication** between identical files, given up with the same store.
- **Resumable uploads to Drive** — uploads buffer whole. Streaming bounds memory, not bytes moved.
- **Delta transfer** — a changed file travels in full.

All four are in the README's [Todos](../README.md#todos) with the same framing.

## 8. Two rules this project paid for, carried forward

Kept here because they are not in any doc and each cost defects to learn — the long version is §6 of
the [previous backlog](./2026-08-14_12h04.open-work.session.md):

- **Defects are found by writing the thing that *uses* the feature**, not by reading the code that
  implements it. Three throwaway probes, a retry loop and a fifty-line headless user found two cases
  of silent data loss and one pass that reported success with the two folders in different states.
  The fast-path session then repeated the lesson from the other side: three of its four first-run
  failures were the fixture lying, not the code.
- **A test can hold a bug in place.** `CopyReason 'block'` was declared, documented and named in the
  contract, and never written, because one test asserted the wrong label and the code listened to the
  test rather than to the three documents.

# Extension — 2026-08-14 19h12

**Summary**: §2 is done and the backlog gained an item the session found on its way through — one
that outranks everything else left.

**§2, the explorer's sync surface, landed in `26387f5`**
([session](./2026-08-14_12h49.explorer-sync-surface.session.md)). 21 tests, `model.ts` at 72.50% of
statements and 81.30% of functions, and one defect fixed: both retry loops replaced the accumulated
decisions with the latest dialog's answers, so a person's answer was dropped whenever a second
conflict appeared while they were reading the first — two disputes and a slow hand were enough to
spend eight dialogs and write nothing. The 20 functions still uncovered are exactly the two clusters
that session deferred: the browser pickers (FSA, Google Identity Services — they need fakes that do
not exist) and the browse lifecycle (`newBrowseFolder`, `deleteBrowseEntry`, `removeSource`,
`regrantSource`, `selectSource`, `closePeer`, `toggleDir`, `selectRoot`, `toggleLog`, `clearLog`),
which is cheap and sits on `explorer-cache.test.ts`'s fixture.

**New, and now the top of this list: a question nobody can answer.** Three peers that each create the
same path on their own can end up asking a person which of two **byte-identical** files keeps the
name, and whether they do depends on the random order of their uuids. The mechanism is §9 of that
session: a peer that adopts a smaller uuid leaves the peers still holding the old one unable to pair
with it, because a uuid the other side *knows* is deliberately not a stranger. Adoption is not a
delete, and nothing records that the old identity became the new one.

**Why this outranks §3 and §4 of the original list**: it is reachable by a consumer doing nothing
wrong, it asks for a decision that cannot be made wrongly *or* rightly — the two versions are the
same bytes — and it is invisible to the suite. `stabilise()` answers every conflict automatically, so
a mesh that had to stop and ask converges exactly like one that never did. The detector is the first
half of the fix: **a question whose two sides carry the same hash is one the engine should have
settled itself**, and asserting that in the shared helper would have caught this the day it was
written. Expect it to go red on some seeds before it goes green — that is the point of it.

**Revised order**: the detector and the identity alias (one session, in that order) → the browse
lifecycle → the browser pickers → §3 `eol` → §4 `location`.
