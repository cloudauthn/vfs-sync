File explorer

One tab per backend — two OPFS folders, memory, and a real folder from your disk through the File System Access API. The tabs are the chain itself, so the far ends never talk directly: changes reach them because every ⇄ handle runs its own sync.

Demo Coverage GitHub npm

Try it: edit notes.md on the first tab and on the last one without syncing in between, then hit Sync the whole chain — the newer edit wins and the other one is preserved as a (conflict …) copy. Switching tabs keeps the open file selected, so you can watch the same path appear on another filesystem.

The explorer is a standalone app in explorer/; this page contributes a heading and one line of script: 

import { mountExplorer } from '../../explorer/src/index';

mountExplorer('#explorer', { opfsRoot: 'my-app-explorer' });

It carries its own scoped styles and reads nothing from the host page, so npm run explorer:build also gives you a static build to serve on its own and drop into an <iframe>.
